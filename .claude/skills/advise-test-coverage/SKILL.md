# advise-test-coverage — 테스트 설계 조언

대상(화면/기능/스펙/diff)을 보고, **무엇을 검증해야 하는지와 놓치기 쉬운 예외·엣지·경계를 먼저 제안**하는 방법. TC 시트를 완성하는 게 아니라 **커버리지 지도를 그려주는** 것.

## 좋은 산출물이란 (품질 기준)

- 정상 경로(happy path)는 1~2줄로 끝. **가치의 8할은 경계·예외 목록에 있다.**
- 각 케이스에 **"왜 위험한가"(현장 영향)** 가 붙어 있다 — 케이스만 나열하지 않는다.
- ISTQB 기법(EP/BVA/상태전이/결정표)으로 **빠짐없이** 훑었다(즉흥 나열 아님).
- 위험도(High/Med/Low)로 **우선순위**가 매겨져 사람 QA가 뭐부터 볼지 안다.
- 문구는 **테스터 언어**(메뉴·화면·조작·결과). 코드 용어는 🛠 노트로 격리.

## 절차

1. **헌법·상태 로드**: `QA_ENGINEER_CONTEXT.md` + `state/qa-engineer-focus.md`.
2. **대상 실물 확인**: 화면이면 소스(ftl/jsp+css)·Figma, 기능이면 코드 분기, diff면 변경 hunk. 추측 금지.
3. **기법으로 훑기** (`TC_DESIGN_GUIDE.md §5` 끌어옴):
   - **EP(동등분할)**: 입력을 유효/무효 클래스로 쪼갬. 각 클래스 대표 1개.
   - **BVA(경계값)**: 각 경계의 min-1 / min / max / max+1. 0·빈값·최대길이·오버플로.
   - **상태전이**: 화면/디바이스 상태(Idle→처리중→완료/에러, 카세트 Empty→Checked 등) 전이 + **불가능해야 할 전이**.
   - **결정표**: 조건 조합(권한 × 모드 × HW상태)로 분기 폭발 잡기.
   - **Positive & Negative**: 되어야 할 것 + **되면 안 되는 것**.
4. **예외 축 강제 훑기** (아래 체크리스트 전부):
   - 빈값 / null / 최대길이 초과 / 특수문자 / 다국어(RTL·긴 번역)
   - 경계 금액·수량 (0, 최소단위, 최대, 초과)
   - HW 실패·타임아웃·중간 중단(전원/네트워크) → 복구·롤백
   - 동시성 / 중복 클릭(더블클릭) / 빠른 연타 / 새로고침(키오스크는 불가가 스펙)
   - 권한별(비활성/숨김) / 모드별(점검·비활성)
   - 다국어 메인 reset 등 **스펙상 정상인 동작**(버그 아님) 구분
5. **위험도·우선순위 부여**: 현장 영향 × 발생 가능성 → High/Med/Low.
6. **TEMPLATE 표로 출력** + 결정 필요 지점은 선택지+추천.

## 언제 쓰지 말 것 (경계)

- TC 시트를 실제로 **작성**(구글시트 생성/셀 채움) → `TC_DESIGN_GUIDE.md §6` 규격으로 직접.
- 코드 유닛 테스트 작성 → `write-unit-tests` skill.
- diff 영향 범위 산정 → `diff-driven-test` skill(이 skill 은 산정된 diff의 케이스 제안엔 쓰임).

## 출력 계약

`references/TEMPLATE.md` 구조로 출력:
1. **한 줄 요약** — 이 대상에서 가장 위험한 곳 1문장.
2. **정상 경로** — 1~2줄(짧게).
3. **커버리지 표** — 케이스 / 기법 / 왜 위험(현장영향) / 위험도. 경계·예외 중심.
4. **놓치기 쉬운 것** — 사람 QA가 흔히 빠뜨리는 축(동시성·복구·다국어·권한).
5. **결정 필요** — 스펙 애매점(선택지+추천, 단정 금지).
