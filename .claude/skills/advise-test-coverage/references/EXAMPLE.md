# [품질 앵커] 테스트 커버리지 조언 — KioskA 현금→칩 교환 금액 확인 화면

> 대상: KioskA 키오스크 현금 투입 후 칩 교환 금액 확인 화면
> 소스 근거: `camanagerbtockiosk/.../cashrecycler` 흐름 + 금액 확정 컨트롤러  ·  작성일: 2026-07-01

## ⚠ 한 줄 요약
투입 금액 경계(최소 교환단위 미만 / 카세트 지급 가능 최대 초과)와 지급 중 하드웨어 중단 시 **돈은 들어갔는데 칩이 안 나오는** 정산 불일치가 가장 위험하다.

## ✅ 정상 경로 (짧게)
- 유효 지폐 투입 → 금액 정상 표시 → 확인 → 칩 정상 지급 → 완료 화면.

## 🔍 커버리지 표 (경계·예외 중심)

| # | 테스트 케이스 (테스터 언어) | 기법 | 왜 위험한가 (현장 영향) | 위험도 |
| :- | :-- | :-- | :-- | :-: |
| 1 | 최소 교환단위보다 1단위 적은 금액 투입 후 확인 | BVA | 교환 불가여야 하는데 진행되면 잔돈 처리 오류 | High |
| 2 | 칩 카세트 지급 가능 최대치를 초과하는 금액 투입 | BVA | 칩 부족 시 부분지급/멈춤 → 정산 불일치 | High |
| 3 | 금액 확인 → **지급 도중 전원/네트워크 차단** | 상태전이 | 현금 수납·칩 미지급 = 고객 손실, 롤백/보류 처리 확인 필요 | High |
| 4 | 확인 버튼 더블클릭·빠른 연타 | Negative | 중복 지급/이중 차감 위험 (kiosk-runtime 더블클릭 가드 확인) | High |
| 5 | 거절 지폐(reject) 반환 후 잔여 금액만으로 확인 | 상태전이 | 반환분이 금액에 잘못 포함되면 과지급 | Med |
| 6 | 점검(비활성) 모드에서 화면 진입 시도 | 결정표 | 비활성인데 진행되면 안 됨(설정 플래그, 잔액 무관) | Med |
| 7 | 다국어(가장 긴 번역) 상태에서 금액·버튼 표시 | EP | 레이아웃 깨짐·버튼 잘림으로 오조작 | Low |

## 🕳 놓치기 쉬운 축
- **동시성/연타**: 확인 연타 이중 지급 → kiosk-runtime 더블클릭 helper 가 이 버튼에 걸렸는지 확인.
- **중단/복구**: 지급 중 잼/전원 → 현금은 수납됐는데 칩 미지급된 상태의 정산 로그·보류 처리.
- **다국어**: 메인 복귀 시 언어 reset 은 **스펙**(버그 아님) — fail 로 올리기 전 확인. [[feedback_spec_check_before_jira]]
- **권한/모드**: 점검 모드 = 잔액 부족 아님, **설정 플래그**. 용어 혼동 주의.
